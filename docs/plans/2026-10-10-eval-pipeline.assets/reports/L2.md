Behaviours follow the plan:
- **Workspace scoping:** reads and updates filter by `workspaceId` wherever the `EvalStore` signature has one.
- **`insertCase`:** uses `onConflictDoNothing({target:[agentId, sourceFindingId]})`. When no row comes back it selects the existing one and returns `created: false`.
- **`insertSuite`:** `run_number` is a `coalesce(max,0)+1` subquery inside the insert. SQLSTATE 23505 (from either unique index) returns `'already_running'`.
- **`listSuites` and `recentSuites`:** both select via `getTableColumns` minus `snapshot`, ordered `started_at desc, run_number desc`. Both return `snapshot: null`. `getSuite` includes the snapshot.
- **`lastResults`:** `selectDistinctOn(case_id)` over `status <> 'running'`, ordered `ran_at desc`.
- **`insertCaseRun`:** returns `undefined` on FK violation 23503.
- **`finish*` and `updateSuiteProgress`:** return `false` when 0 rows are updated.
- **`reapInterrupted`:** sets running suites to `failed` with reason and `finished_at`, and running case runs to `errored` with reason.
- **Aggregates:** `countCasesByAgent` uses a raw `sql<number>` (`count(*)::int`) and `insertSuite` uses a raw `sql` subquery.

Two design choices to know about:
- **Skill-owned cases:** `eval_cases` also holds `ownerKind='skill'` rows, so every case query filters `ownerKind='agent'`.
- **`CaseRunRecord` nulls:** `matchedMustFind`, `mustFindTotal` and `noiseCount` pass through as `null` for running rows. The null→0 mapping is left to the service and route, as the main-session note said.
