## What I built
- `wiring.ts`: `buildEvalService(container, log, opts: Partial<EvalPorts> = {})` fills every `EvalPorts` field.
  - `store = new EvalRepository(container.db)`.
  - `getAgent` / `listAgents` come from `agentsRepo.getById` / `.list`.
  - `resolveSkills` comes from `enabledSkillsForAgent`, mapped with `isSkillUntrusted(skill.source)`.
  - `findingContext` comes from `reviewRepo.findingContext`, with `accepted = !!acceptedAt`, `dismissed = !!dismissedAt` and `agentId = review.agentId ?? null`.
  - `prFilePatch` comes from `reviewRepo.getPrFiles`, matched by path, returning null when missing.
  - `runCase` is `runEvalCase` with `container.llm`, `parseUnifiedDiff` and `Date.now`.
  - `background` is `void task().catch(log.error with redactSecrets)`.
  - `opts` is spread last, so a test can swap a single port.
- `routes.ts` has no composition beyond calling `buildEvalService` once. Every route declares `schema.response`.
  - Polled GETs (`/eval-suite-runs/:id`, `/eval-case-runs/:id`) set `rateLimit: false`.
  - The three run POSTs use `RUN_RATE_LIMIT` (`{max: 10, timeWindow: '1 minute'}`, defined in `eval/constants.ts`).
  - `POST /findings/:id/eval-case` answers 201 when the case is new and 200 when it already exists (AC-11).
  - `GET /eval-suite-runs/compare` is registered before `/:id`.
- `schemas.ts` holds `CompareQuery`, `OkResponse` and `CASE_WRITE_BODY_LIMIT`.
- **Body limit chosen:** 256 KB (`256 * 1024`), set as a route `bodyLimit` on `POST /agents/:id/eval-cases` and `PUT /eval-cases/:id`. The global limit stays 1 MB. The service still enforces the 64 KB diff rule with a 422 (AC-8). The extra headroom covers the PR title and body, expectations and notes. A body over 256 KB gets Fastify's 413 before parsing.
- `app.ts`: after the agent-run reaper, a separate non-fatal try/catch calls `buildEvalService(container, app.log).reapInterrupted()` and logs the counts. It imports `buildEvalService` directly from `modules/eval/wiring.js`.
